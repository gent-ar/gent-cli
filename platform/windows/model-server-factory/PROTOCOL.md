# Configured server-context model worker (experimental, off by default)

Build this component from the separately verified llama.cpp b10545 source in UPSTREAM.json. It links upstream server_context/server_routes and never constructs or starts server_http_context. CPU-only static backend; no RPC/GPU, subprocess tools, socket listener or model-server fallback.

Launch: `gent-contained-model-factory --config <absolute-json-path> <sha256> <nonce32hex>`. The configuration and model are held read-only, deny write/delete, and their SHA256 values checked before model loading. Configuration is strict schema1, <=16KiB: modelPath/modelSha256/modelId, contextTokens512..32768, maxOutputTokens1..24576 and below context, threads1..8, reasoningBudget0..3072, enableThinking, templateKwargs<=32keys, optional paired templatePath/templateSha256. Parent catalog validation is stricter (minimum context4096 and exact verified model size/hash). Only compiled catalog templates can be materialized by the factory. No client supplies runtime authority or filenames.

Existing nonce-bound wire: input GENTSR01+32-byte nonce, ready GENTSD01+nonce after model/context load. Each request is u32LE-length plus JSON envelope containing method/path/body string. Envelope<=256KiB, body<=128KiB. Routes health/models/chat/apply-template are native-worker allowlisted; broker/actor allow only health/models/chat. Chat passes unmodified body JSON to upstream routes; only function tools, no tool execution in this process. Response frames contain bounded status/contentType metadata then unmodified JSON/SSE chunks and a zero-length terminator. Data chunk<=32KiB, total<=4MiB, metadata<=32KiB. Native tool_choice compatibility is upstream string auto/none/required; named-function objects are not promised.

Parent WindowsModelFactory requires compiled GENT_CONTAINED_MODEL_MANIFEST_SHA256 and exact packaged helper/worker manifest, immutable model/SDK/config/template/OS pins, and the existing native protected/signature OS verifier. Its model PSEC has network Disabled, a private read-only workspace and no user-workspace grant. The authenticated ProviderGatewayLease checks bearer/run/SDK binding before dispatch; no bearer or request headers enter the model process. Streaming failure after headers truncates the connection without a second HTTP status or successful final chunk.

Actor queue1/events2 provide bounded backpressure. Model lifetime is one run; cancellation retires the whole model scope/cache. Native scope:32requests, no Job CPU limit (a slow reply must not kill the worker mid-turn; memory and process limits and run teardown still bound it); actor:300s per response. No unbounded conversation or in-place cancellation/reuse claim. ScopeKnown requires native reserved settled exit; Unknown retains roots, handles and lifetime owners. ACP resource pins transfer into the gateway lease before launch, including launch-error quarantine.

This optional component does not enable Claurst's permission backend, sign a distribution, or prove contained Claurst ACP/MCP/four-mode behavior. Ordinary canonical root overlap checks still need physical alias hardening before production enablement. The existing legacy host route is unchanged outside contained policies. Known reviewed QA proofs are recorded in the integration checkpoint, including30 focused regressions, real authenticated gateway JSON/SSE/Unknown and real catalog-bound model caller/readiness/summarizer; no Claurst SDK prompt in those proofs.
