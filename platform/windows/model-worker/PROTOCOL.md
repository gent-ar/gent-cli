# Contained llama library worker

This optional Windows target uses the official llama.cpp b10545 C API and CPU backend. It has no socket implementation and does not launch llama-server. It is not yet selected by the Claurst factory.

The trusted launcher must verify and retain exact worker, library, CPU backend, OS loader closure and model file identities, and launch through Gent PSEC with no networking capabilities. Pass only public paths and a fresh lowercase 32-hex run nonce as argv: `worker runtime-directory model.gguf nonce`. The runtime directory is absolute. The worker explicitly loads ggml.dll, ggml-cpu-x64.dll and llama.dll; Before backend loading, process-local default DLL search is restricted to System32 plus exactly the reviewed runtime directory, which is added with AddDllDirectory. Explicit LoadLibraryEx calls also restrict dependency search to the DLL directory and System32; upstream backend LoadLibraryW therefore inherits the restricted process-local defaults. This changes no machine or user loader setting. No prompt or credential goes in argv. The parent must not grant the runtime directory recursively; use finite pinned files.

All integers are little-endian u32. The first stdin bytes are `GENTLM01` followed by the 32-byte nonce. After validating this binding and loading the model, stdout emits `GENTLL01` and the nonce. When used through the native helper, consume and verify the helper's separate authenticated lifecycle proof line first.

Serial request: prompt-byte-count, maximum-generated-tokens, UTF-8 prompt bytes. Prompt count 1..65536, generated tokens 1..64, combined token context <=1024. NUL and malformed UTF-8 are rejected. Request count zero closes normally; at most 32 requests are accepted per process. Each response is zero or more token-byte frames (length 1..16384), followed by length zero. Token frames can split UTF-8 codepoints; decode only with an incremental decoder or after concatenation. Maximum output is 1MiB/request. A fatal error closes the process with code65 and a static diagnostic on stderr (llama/ggml log callbacks discard raw model metadata, paths and messages); an incomplete response is never success. No JSON/HTTP/tool-call equivalence is implied.

The model is loaded once. Context memory and greedy sampler are reset between requests; CPU generation uses one thread with GPU layers zero. This initial component supports completion text only. Model chat templates, tool-call semantics, HTTP/SSE translation, readiness ownership and installed model-lock composition still require explicit integration; do not advertise Claurst complete containment from this component alone.

The outer native helper owns process limits and cancellation. EOF, timeout or revoke must close/terminate the whole owned PSEC scope, then await its exact Job settlement. Killing only this worker or observing a helper wait is insufficient. Unknown outcomes retain model/runtime pins and leases under the existing quarantine contract. No production authority or permission allowlist is enabled here.

The independent acceptance uses the upstream pinned stories15M-q4_0 test GGUF (SHA256 66967fbece6dbe97886593fdbb73589584927e29119ec31f08090732d1861739), not a user's model. Host and cap0-PSEC each served two different requests from one load and returned identical token bytes. AF_UNIX bind was separately denied with WSA10013 under the same cap0 posture. Neither test claims physical LAN isolation or a full chat provider.
